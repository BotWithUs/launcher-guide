Using the launcher from a command line

The launcher ships a companion command-line tool, bwu_cli.exe. It reads and writes exactly the same settings as the window does, so anything you set in one shows up in the other.

You do not need this

Everything on this page has a button somewhere in the launcher. Reach for the CLI when you want to script your own setup, work over a remote session, or drive a machine without clicking through a window.

Running it

bwu_cli.exe sits next to the launcher itself:

# PowerShell
cd "$env:LOCALAPPDATA\Programs\BotWithUs\Launcher"
.\bwu_cli.exe --help

Every command group also takes --help:

.\bwu_cli.exe scripting --help

Commands print what they did and set a non-zero exit code on failure, so they behave properly inside a script.

Signing in

CommandWhat it does
versionPrint the launcher version. Quote this when asking for help.
loginSign in to BotWithUs, the same browser flow the window uses.
login --token <token>Sign in with a token you already hold, without the browser.
statusShow who is signed in.
logoutSign out and clear the saved sign-in on this machine.

Accounts

Jagex accounts have their own group:

CommandWhat it does
jagex loginAdd a Jagex account. Opens the same sign-in and consent flow as Add Jagex account, and saves the characters it finds.
jagex listList your saved characters, one per line — easy to pipe into something else. This is where you get the character id the next command wants.
jagex launch <character>Launch that character, same as pressing Launch on its row.
jagex label <uuid> "<nickname>"Set the nickname shown in the launcher. Pass "" to clear it.
jagex remove <uuid>Forget an account — deletes its saved session and character list. Game progress is not affected.

The BotWithUs-side account list has two commands of its own: accounts list, and accounts remove <uuid|name>.

# add an account, then see what came back
.\bwu_cli.exe jagex login
.\bwu_cli.exe jagex list

The emailed sign-in code

CommandWhat it does
jagex auto-codePrint whether auto-code is currently on or off.
jagex auto-code on · offTurn it on or off. This is the same setting as the Fill in the emailed code for me toggle — one preference, both front ends.
jagex mail-setupPrint the mail-client rule instructions for your machine.
jagex mail-setup --probeWait for one test message so you can check your rule works before relying on it during a real sign-in.

What auto-code is, and when it can and cannot work: see the Accounts page.

Scripting frameworks

This group is the framework editor in command form — the same four fields, the same saved list.

CommandWhat it does
scripting listShow every configured framework, numbered, with the command each one runs and its id.
scripting add …Add one. Options below.
scripting launch <ref>Launch one, same as pressing Launch in Script Hub.
scripting remove <ref>Remove one from the launcher. Deletes nothing on disk.

<ref> is whichever is handiest: the id, the name, or the position number from scripting list.

Options for scripting add

OptionMeaning
--name <name>Required. The label you will see in the launcher.
--javaRun it with Java. With this flag --program is optional — leave it off and a Java runtime is found for you.
--program <path>The executable to run. Required unless you passed --java.
--args "…"Arguments, passed through verbatim. Quote the whole thing.
--cwd <folder>Working folder. Relative paths in --args are measured from here.
 
# a Java framework of your own
.\bwu_cli.exe scripting add --name "My framework" --java `
    --args "-Xmx4G -jar C:\Tools\my-framework.jar" `
    --cwd "C:\Tools"

# a plain executable
.\bwu_cli.exe scripting add --name "Helper" --program "C:\Tools\helper.exe"

# check it, then run it
.\bwu_cli.exe scripting list
.\bwu_cli.exe scripting launch "My framework"
The same rules apply here

--args is the ARGUMENTS box under another name, so everything on the arguments page holds: leave the runtime unset on the bundled entry, add to its arguments rather than rewriting them, and quote paths with spaces.

Repairing a download

If something the launcher downloaded looks damaged — the framework refusing to start after a failed update is the usual symptom — fetch it again:

CommandWhat it does
agent refreshRe-download the launcher’s game-side component.
assets refreshRe-download the cached game data.

Both are safe to run at any time, and both leave your accounts and frameworks alone.

Anything not listed here

--help will show a few commands this page does not cover. Those exist for development builds and internal testing: they are unsupported, they change without notice, and they are deliberately undocumented. If you need something you cannot find here, ask in support rather than guessing at them.
