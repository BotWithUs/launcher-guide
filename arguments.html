Editing a framework’s arguments

For people who want more memory, an extra flag, or their own framework entirely. Most users never need this page — the bundled entry works as shipped.

Where the editor is

  1. Open Preferences

    Bottom of the sidebar, under SETTINGS.

  2. Scroll to SCRIPTING FRAMEWORKS

    Each configured framework is listed with its name, its JAVA or EXE chip, and a preview of the command it runs.

  3. Press Edit, or Add framework

    Both open the same editor. Remove deletes the entry from the launcher — it never deletes anything on disk.

The fields

FieldWhat it does
TYPE Executable runs any .exe directly. Java runs a Java program.
NAME Your label for the entry. Required — leaving it blank gives you “Give this framework a name so you can find it later.”
EXECUTABLE
(Executable type)		 The program to run. Required — without it you get “Choose an executable to run, or switch to Java.” Browse… fills it in for you.
JAVA RUNTIME (OPTIONAL)
(Java type)		 Which Java to use. Leave it blank and the launcher picks one for you.
ARGUMENTS Passed to the program exactly as you type them — the launcher does not rewrite, sort or second-guess this box.
WORKING FOLDER (OPTIONAL) The folder the program starts in, which is what any relative path in ARGUMENTS is measured from. Blank means it inherits the launcher’s own folder.

Save writes the entry and closes the editor; Cancel throws the changes away. The command preview in the list updates immediately, so you can check what you built without launching it.

Changing the bundled BotWithUs (Java) entry

This entry is set up by the launcher. You can add to it, and there are two rules worth following to the letter.

Leave JAVA RUNTIME blank

Blank lets the launcher use the Java runtime it installed for you, and keeps working when an update replaces it. Pointing this entry at your own JDK is not supported: your own local scripts may well run, while Script Market scripts quietly do not — which looks like the Market being broken rather than a wrong runtime.

Add to the arguments, never rewrite them

Treat what is already in ARGUMENTS as one block that belongs to the launcher. Put your own flags in front of it, leave the rest untouched, and do not reorder it. Deleting part of that line is the usual cause of a framework that starts and then does nothing useful.

Things that are safe to add

AddEffect
-Xmx4GLet the framework use up to 4 GB of memory. Useful with many clients open; pick a number your PC can actually spare.
-Xms1GStart with 1 GB already reserved.
-Dname=valueAny property your own scripts read.

So an entry whose arguments currently read <the launcher’s line> becomes:

-Xmx4G <the launcher’s line, unchanged>
Write the original down first

Before you touch it, copy the existing ARGUMENTS text somewhere safe. It is the quickest way back if an edit goes wrong — and see Start over if you did not.

Adding your own framework

Writing your own framework, or running someone else’s? Add it as a second entry and launch it from Script Hub alongside the bundled one.

An executable

  1. TYPE → Executable
  2. NAME → anything, e.g. My framework
  3. EXECUTABLE → Browse… to your .exe
  4. ARGUMENTS → whatever your program takes, or leave it empty

A Java program

  1. TYPE → Java
  2. JAVA RUNTIME → leave blank

    Blank looks for a Java runtime for you: the one the launcher installed first, then JAVA_HOME, then your PATH. Fill it in only if you specifically need a particular Java.

  3. ARGUMENTS → -jar C:\Tools\my-framework.jar
  4. WORKING FOLDER → where your program expects to run

    Set this if your program reads config or writes logs beside itself.

Rules for the arguments box

  • Order matters in Java mode. Java’s own options first, then what to run (-jar …), then that program’s arguments. Anything after -jar yourfile.jar goes to your program, not to Java.
  • Quote paths containing spaces — -jar "C:\My Tools\framework.jar".
  • Relative paths follow the working folder, so if you set one, you can keep the arguments short.
  • The text is used verbatim. A stray character stays a stray character.

Start over

Deleted BotWithUs (Java), or edited it into something that no longer works? You can reset every framework back to the shipped default:

  1. Close the launcher
  2. Delete this file 
    %LOCALAPPDATA%\BotWithUs\Launcher\scripting_hosts.json

    Paste that path straight into the File Explorer address bar.

  3. Open the launcher again

    BotWithUs (Java) is back, configured as it was on day one.

This wipes your own entries too

That file holds every framework, not just the bundled one. Copy down anything you added yourself before deleting it — you will be re-entering it by hand.
